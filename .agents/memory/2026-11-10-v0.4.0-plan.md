## Rules for this release

- Branch **`feat/v0.4.0`** from `main` at the `v0.3.0` tag; merged into `dev` by pull
  request when the release is ready, then `dev` → `main` and the tag, as for 0.3.0.
- Rounds are numbered **when each starts** (ROADMAP's working rule), in the order below,
  one at a time; letters here are placeholders, not round numbers.
- **Each round starts with a kickoff review** (owner: "Khi start round sẽ phân tích đánh
  giá lại 1 lần nữa"), written into the round's Plan before any code:
  1. Re-read this plan's entry and what changed since (code, earlier rounds, the owner's
     notes from using the last build).
  2. Map the code the round touches (files, functions, tests), as the 2026-11-09 review did.
  3. A quick outside check where the round depends on it (crates, terminals, competitors).
  4. Critique: what in the entry is wrong, risky or bigger than thought; a better way if any.
  5. Steps, tests that fail without each change, sizes, risks; the owner's decisions listed.
  6. The owner says go; then Do.
- Every fix with a test that fails without it; fmt, clippy (Linux, Windows, macOS
  targets), the full suite, `cargo deny` before each commit series; CI by pull request.

## A. Foundation (S–M) — first, because every later round lands in `app.rs`

Goal: make v0.4's features cheap to add and Windows testable; no user-visible change.

1. **Split `app.rs`** (7,729 lines, ~30% of the crate) along seams it already has:
   key and mouse dispatch, jobs (start, pump, finish, quit/stop), modal dispatch
   (`perform_cmd`, `ModalAct`), settings save, graphics sync, start-up (`boot`, recovery,
   probe), session save. `impl App` blocks in `app/<seam>.rs`, moved verbatim first
   (one commit per seam), then tidied. Guard: the whole suite, unchanged, green at each
   commit.
2. **Windows end to end**: the pty suite is Unix only. A small Windows-only test that
   starts `xdevcmd.exe` under ConPTY (portable-pty supports it), reads a frame through
   vt100, presses F10. In CI's Windows job.
3. **Housekeeping the owner authorises**: ROADMAP rewritten from the final review (stale
   statuses, numbering, v0.4 order), `reference/ui.md` keys, `reference/gotchas.md`
   vt100/tui-term notes; promotions proposed in Rounds 016/017 and the memories.
4. **Packages follow-up from 0.3.0** (owner's accounts): Homebrew tap
   `nci-gis/homebrew-xdevcmd`, Scoop bucket, winget submission, `cargo binstall`
   metadata. README's install section trimmed to what exists.

Risks: a split that changes behaviour by accident (mitigated: move only, no edits, in the
first commits); ConPTY quirks in CI.

## B. Paths in the shell's output (item 30, part 1; M)

Goal: in the history view (Shift+F12), paths that exist on disk are marked, and act.

- Recognise: plain paths, `path:line[:col]`, Python's `File "x.py", line 12`, Node/JS
  `at f (x.js:3:7)`, MSBuild `x.cs(12,5)`, Windows `C:\…`, `~/…`; relative ones resolved
  against **the shell's directory when the command ran** (OSC 133 marks give command
  boundaries, OSC 7/`/proc` the directory), never beyond moving a pane.
- Act: Enter takes the pane to the file (cursor on it); F3/F4 open it at that line;
  a stale or unreadable path says so, never guesses.
- Tests: a recogniser table (unit, each form, false positives like URLs and versions);
  pty: `ls`, `grep -n`, a Python traceback in the panel → Shift+F12 → Enter → the pane is
  there.
- Kickoff question: mark in the live panel too, or the history view only (plan: history
  view only; the live screen belongs to the program).

## C. Panelize and find into a panel (item 30, part 2; M)

Goal: mc's most-praised feature, upgraded — a list of paths becomes a panel that F5/F6/F8,
marking and rename work on.

- Sources: chosen lines of the history view; a whole command's output (`rg -l`, `git
  status --porcelain`, `find`), run on request in the shell's directory; Alt+F7 find
  results (a results pane exists: reuse it).
- Built-in content search straight into a panel (name + content, as Alt+F7 does) for
  machines without `rg`.
- The panel is virtual: names relative to their base, missing files shown as errors (hard
  rule 4), refresh on demand.
- Tests: render (a panel from a fixed list), pty (`printf` paths → panelize → F5 copies
  them), the policy walls (read-only, `--root`: entries outside are refused).

## D. Syntax-highlighted viewer (S–M)

Goal: code reads like code in F3 and quick view; search matches highlighted.

- Measure before choosing: `syntect` with a trimmed syntax set vs a lighter highlighter;
  budget about +1.5 MB on the static binary; licences through `cargo deny`.
- Off by setting (`[viewer] highlight`), off in hex, off past a size cap; 256/16-colour
  terminals degrade through the theme.
- Tests: render of a small Rust and Python file; the size cap; search highlight.

## E. One directory history (item 29; S–M)

Goal: Alt+J (and the bookmarks) know directories visited by panes and by shells (OSC 7).

- One list per session, deduplicated, newest first, shell entries marked; persisted with
  the session; the shell's entries only from trusted reports (Round 016's rules).
- Tests: unit (merge and order), pty (`cd` in the shell → Alt+J lists it).

## F. Remote: the owner's decision first (S to L)

Evidence: SFTP is the most requested gap (yazi #611, superfile #134) and the main reason an
mc or Far user would not switch. Hard rule 2 ("no network calls") and ROADMAP ("No SFTP")
stand until the owner changes them.

- (a) **A panel over the user's own `ssh`**: xdevcmd runs the system `ssh` the user names
  (`ssh host` with a small shell protocol, as mc's shell link, or `sftp -b`), so it never
  opens a socket itself, fetches nothing, sends nothing anywhere else. Needs hard rule 2
  reworded by the owner. Spike first (S): list, copy in, copy out; then decide (L).
- (b) **No remote**, said plainly in the README with the workflow that replaces it (ssh in
  the panel, a copy of xdevcmd on the server, `scp` from the panel).
