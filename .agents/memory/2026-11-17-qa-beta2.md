## Problem

The owner doubted that the tests prove what a real user expects, rather than restating
the code.

## Finding

- Audit (4 agents, docs as the oracle, 319 promises): PROVES 109 · CONFIRMS 137 ·
  MISSING 57 · MANUAL 16+. Most CONFIRMS check screen text only.
- Hunt (4 agents, the real binary in a sandbox) found three P0 classes, each reproduced
  again by the main session:
  1. F5 of a folder onto a destination where that name is a symlink to a folder
     elsewhere: the plan says "⛔ skipped", the job writes new files through the link,
     outside the target.
  2. F6 replacing a file on the same drive: the old file is deleted for good, while the
     dialog says "a file replaced goes to the trash"; Ctrl+Z cannot bring it back.
  3. Alt+C while the shell holds an open double quote or a here-doc: a folder named
     `$(touch PWNED)` runs (the single-quoted name is inside the user's double quotes).
     shell.md called this case harmless.
- P1s: F6 of a folder onto a same-named folder is a dead end (os error 39); a killed
  Alt+Y is not offered Continue and its checkpoint is deleted; Ctrl+Z refuses to undo a
  rename-many that swapped names; F2/Shift+F2/pack turn non-UTF-8 bytes into U+FFFD on
  disk; two tar entries with different non-UTF-8 names merge; Alt+C into a bash
  `read -s` prompt; a `[[menu]]` command with `%f` inside the user's own quotes runs
  the name; a refused menu command leaves focus in a busy shell.

## Evidence

- Reports: `2026-11-17-qa-beta2/` (audit-*.md, hunt-*.md, brief.md), with exact repro
  commands.

## Recommendation

Fix the three P0 classes red-first before the cut, with a red-team on each; triage the
P1s with the owner. Run the QA skill again at rc.1, wider than data paths.

**Known issues for the beta.2 notes (rc.1 work):** F6 of a folder onto a same-named folder
on one drive is a dead end (os error 39, nothing lost); a killed Alt+Y is not offered
Continue and its checkpoint is removed (nothing lost); Ctrl+Z refuses a rename-many that
swapped names; Alt+F5 packing and tar extraction turn non-UTF-8 names into U+FFFD (two
such tar entries can merge); bash's `read -s` is not seen as busy; an open single quote
in fish or PowerShell; a refused menu command leaves focus in a busy shell; the plan
table shows ℹ where docs say ⚠ and is not worst-first. P2s: see the hunt reports.

**Lesson:** the first shell fix passed its own test and one user path; the red-team broke
it three ways in minutes. Fixing the cause (what is typed) beat detecting the context
(where it lands). Red-team every data-path or injection fix, every time.
